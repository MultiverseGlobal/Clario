# Simple Design Process

Use this loop for every feature, page, flow, or redesign. Keep the process short enough to use daily and rigorous enough to catch expensive mistakes early.

## 1. Understand

Write one sentence for the user, one sentence for the user’s job, and one sentence for the product’s promise. Identify the primary action and the most damaging failure. If these are unclear, do not begin with colors or components.

## 2. Structure

Map the user flow from entry to success. List the screens, decisions, required information, empty states, errors, permissions, loading states, and exit paths. Sketch the page hierarchy before selecting a visual style.

## 3. Direct

Choose one visual direction that belongs to the product. Define a small semantic token set, type roles, spacing rhythm, layout behavior, component grammar, material rules, and one signature moment. State what you are deliberately not using.

## 4. Build

Implement foundations, then the core flow, then states, then responsive behavior, then motion and visual polish. Reuse accessible primitives. Keep content realistic. Never let the hero or decoration delay the usable flow.

## 5. Critique

Review the result at multiple widths and input modes. Ask what the user notices first, where they hesitate, what looks generic, what is inaccessible, what is slow, and what can be removed. Fix the largest comprehension or usability problem before adding another visual effect.

## Decision rule

When two choices look equally attractive, choose the one that is easier to understand, more robust across devices, simpler to maintain, more accessible, and more specific to the product. Taste is not maximal decoration. Taste is knowing what to leave out.
